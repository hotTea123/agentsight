# Go 接入与构建示例

面向拿到二进制交付包的 ICAgent 开发者。这里编译的是 Go 消费程序，**不是重新编译
AgentSight**。只需匹配的运行依赖和 Go/cgo 工具链，不需要 Rust/Cargo。
完整可构建示例：[examples/go/main.go](../examples/go/main.go)。接口契约见
[接口说明](01-动态库接口说明.md)。

## 1. 交付目录和前置条件

```text
交付包根目录/
├── lib/libagentsight.so
├── lib/libagentsight_tool_marker.so
├── include/agentsight.h
├── examples/go/main.go
├── docs/                         本套文档
├── README.md
└── TEST_REPORT.md
```

构建消费示例需要 Go、启用 cgo、可用的本机 C 编译器。示例使用 unsafe.Slice，要求
Go 1.17 或以上语法能力；本次实际验证为 Go 1.21.4 / Linux ARM64，不宣称验证了所有版本。
运行环境要求：

- 当前交付 `.so` 为 Linux ARM64；示例的 amd64 build tag 不代表本包能在 amd64 运行。
- 配套头文件和库必须同版本。不能只替换 `.so` 而继续使用旧结构布局。
- 当前依赖 libelf.so.1、libz.so.1、libgcc_s.so.1、glibc；最高所需 glibc 符号版本 GLIBC_2.34。
- 无采集模式不挂探针；真实采集另需满足内核、权限、procfs、Python 和 marker 条件。
- 跨架构 cgo 编译还涉及交叉 C 工具链、目标系统依赖和对应 `.so`，不属于本例验证范围。

源码仓库通常没有 `agentsight-ffi/lib/`。以下命令从**二进制交付包根目录**运行，
不是从任意源码目录直接运行。运行前可用 `sha256sum -c SHA256SUMS` 核对文件完整性。

## 2. 编译与无采集检查

```sh
# 先进入解压后的交付包根目录
CGO_ENABLED=1 GO111MODULE=off go build -a -o /tmp/agentsight-host ./examples/go
/tmp/agentsight-host
```

该模式覆盖版本检查、init、get_eventfd、get_stats、free，不调用 start，不采集业务。
预期输出包含：

```text
Go/cgo ABI smoke passed: eventfd=<非负整数> state=0 config=32 event=88 stats=192
```

fd 数字不固定。结构大小仅用于核对当前产物，宿主实现使用 sizeof，不硬编码。
`-a` 强制重编译，防止 Go 缓存未发现包目录外头文件变化；生产项目替换头文件/库后
也需要确保 cgo 相关包重新编译。此步骤成功不代表实际采集和上报通过。

## 3. 链接配置是什么意思

示例包含：

```go
/*
#cgo CFLAGS: -I${SRCDIR}/../../include
#cgo LDFLAGS: -L${SRCDIR}/../../lib -lagentsight -Wl,-rpath,${SRCDIR}/../../lib
#include "agentsight.h"
*/
import "C"
```

- `${SRCDIR}` 指当前 Go 源文件目录。
- `-I` 找头文件，`-L` 找链接库，`-lagentsight` 链接 libagentsight.so。
- rpath 指示运行时加载器寻找库的位置；本例将源码对应的交付目录位置嵌入可执行文件。
  把可执行文件单独移动到另一台机器，不会把 `.so` 一起打包，也不保证原路径仍存在。
- 正式产品需约定库安装位置及运行时加载策略，不能照搬开发机绝对路径。
- 本例是**直接链接**；缺少 `.so` 或依赖库可能在 Go main 执行前失败。若要求“增强库
  缺失不影响 ICAgent 启动”，应由 ICAgent 实现可选运行时加载等方案，本例不提供该封装。

## 4. 配置和完整处理步骤

示例的 run() 按以下步骤执行，覆盖全部11个公开接口：

1. 对比 `agentsight_abi_version()` 与头文件常量。
2. `agentsight_init(&h)`，注册退出时释放，检查释放错误。
3. `agentsight_get_eventfd(h)` 获取借用通知 fd。
4. 无参数时只查询统计；`-capture` 模式才进入下面流程。
5. 清零配置，填写 sizeof、ABI、C.CString 的 procfs_root；调用 set_config。
6. 调用 start，分配 C 内存中的事件指针槽数组。
7. poll 等待通知，调用 poll_events 分批取出事件。
8. 将 ID、时间、类型和 JSON 复制到 Go 内存，立即 free_event，然后打印复制后的内容。
9. 周期查询 stats，打印目标状态变化；FAILED 或调用失败时报告错误。
10. 到达指定时间后 stop，再排空剩余事件，最后 free。

默认使用库的队列和发现参数。需要自定义时，在 set_config 前设置
`queue_capacity`、`max_queue_bytes`、`discovery_interval_ms`，范围见接口文档。

内存规则：

| 分配 | 使用后释放 |
|---|---|
| C.CString(procfs_root) | C.free，库在 set_config 内已经复制 |
| C.malloc 的错误缓冲区/指针槽 | C.free |
| poll 返回的每个事件 | agentsight_free_event，不能 C.free |
| Go 复制后的 payload/ID | Go 管理，不引用释放后的原生内存 |

示例通过返回错误处理 API 负值；get_last_error 文本只是辅助，缓冲区不足时标记截断。
系统 poll 的 EINTR 会重试，其他等待错误会报告。eventfd 不由示例 read/write/close。

## 5. 真实采集运行方式（需要另行安排联调）

以下命令会启动真实发现和采集，不属于无采集冒烟检查：

```sh
/tmp/agentsight-host -capture -seconds 30 -procfs-root /proc
```

前置条件：

1. 宿主能够加载 eBPF 并挂载 uprobe，具有所需内核能力及权限。
2. procfs 与 PID namespace 满足宿主进程可见性要求，不只是挂一个 /proc 目录。
3. Jiuwen 使用支持的 Python 构建，加载真实 marker。
4. 正式侵入式插桩在工具开始时 bind、结束时 unbind，且 OTel context 有效并被采样。
5. 等 target_state=3（READY）后执行工具内文件/程序操作。

可能先看到 WAITING=1、ATTACHING=2，最终 READY=3；业务不存在时持续 WAITING 正常。
DEGRADED=4 应检查错误、权限、Python 兼容和候选冲突，不通过猜偏移绕过。
示例打印事件头及 JSON，不生成 OTel span、不上报 Jaeger。

可在独立联调环境使用不存在的 procfs 路径检查降级，但这会调用 start：

```sh
/tmp/agentsight-host -capture -seconds 2 -procfs-root /nonexistent-agentsight-test/proc
```

预期降级且能停止，不是成功挂载的验证。不要与另一套真实采集混跑并据此评估业务结果。

## 6. 常见问题

| 错误/现象 | 排查 |
|---|---|
| cannot find -lagentsight | 是否在完整交付目录编译，lib目录是否存在 |
| incompatible / wrong ELF class / 架构错误 | 库与宿主 CPU、编译目标是否匹配 |
| shared libraries / GLIBC_x.y not found | 运行时路径、依赖及系统版本是否满足；不是再安装 Rust |
| stats buffer too small | 是否混用头文件，重新 `go build -a` |
| 无事件但 RUNNING | 查看 target_state；确认 READY 后发生了绑定工具内行为 |
| 收到事件但 Jaeger 没有 | 本示例不负责上报；需要 ICAgent 完成转换和 trace 管道接入 |

## 7. 示例与正式 ICAgent 的差距

示例以固定秒数运行并打印敏感的原始证据，适用于受控测试，不是生产插件。
未实现生产信号管理、配置热切换封装、隐私脱敏、上报队列/重试、业务资源归属和 OTel 导出。
异常提前退出时 free 可能丢弃尚未消费数据；生产应按验收策略处理并计数。
高负载下不要把同步打印当作真实消费性能。详细职责见[ICAgent适配需求](04-ICAgent适配需求.md)。

## 8. 与源码构建的区别

仅需接入二进制时，不执行 make/cargo。库维护者修改 Rust/C/eBPF 代码并重新出包时，
需要与目标架构一致的 Linux 环境、Rust 1.88+、C 编译器、Clang/BPF、make、libelf/zlib
开发文件及完整的 libbpf/bpftool 子模块，相关命令见源码 README。
Go 消费程序只需在满足运行依赖和 Go/cgo 工具链要求的环境中编译，不需要源码构建环境。
