# 当前版本功能与边界

本文描述本次 Linux ARM64 / ABI v2 交付的实际能力，不代表上游 AgentSight 全量能力，
也不代表 ICAgent 已经集成上线。二进制构建来源见交付包根目录的 BUILD_INFO.md，
测试来源见 [TEST_REPORT](../TEST_REPORT.md)。源码目录也可直接阅读 TEST_REPORT。

## 1. 功能定位与两个库

| 交付物 | 加载方 | 作用 |
|---|---|---|
| libagentsight.so | ICAgent | 自动发现、Python适配、eBPF采集、证据关联、事件读取与诊断 |
| libagentsight_tool_marker.so | Jiuwen侵入式插桩 | 在原始工具span生命周期提供bind/unbind的稳定native边界 |
| agentsight.h | ICAgent编译使用 | 采集库C ABI、配置/事件/统计定义 |

采集库使用 Rust FFI + C/libbpf 核心，在 ICAgent 进程的工作线程内运行，不启动独立
AgentSight/collector/process 子进程，不要求运行机器安装 Rust。marker 不负责采集、
网络通信或上报，必须由业务侧完成接线；仅部署采集库不能替代侵入式插桩。

当前不包含原 collector 的数据库、Tokio运行时、LLM解析、独立OTLP上报等能力。
这版 `.so` 输出的是**已关联的证据事件**，不是已经完成的 OTel span。

## 2. 工具关联如何完成

1. 原始侵入式插桩创建正式 tool span。
2. bridge 调用 marker bind，将 Task 标识和 trace/span/flags 传入。
3. 同步触发 marker uprobe，eBPF 记录绑定。
4. 系统行为发生时，结合 Task、父 Task、PyContext 或短子进程继承关系，复制工具身份到证据。
5. 库只向外提供关联有效且 sampled 的四类事件。
6. ICAgent 创建新的证据子 span，复用 trace ID，以原始 tool span ID 为父 ID并上报。
7. 工具结束走 unbind，避免后续无关行为沿用绑定。

关联不依赖事后时间窗口、文件路径、PID或名称猜测。原始工具span结束后才收到证据，
也不需要重新打开或修改该工具span；增强的是整个trace的证据层级。

## 3. 自动发现和运行生命周期

- ICAgent可先启动；库先启动发现线程，没有目标时 WAITING。
- 扫描目标procfs，识别实际映射的约定 marker 名称，并验证三个约定函数符号。
- 以 PID + 进程启动标识区分实例，检查实际映射文件；不是按 cmdline 白名单选目标。
- 当前按节点一个独立Jiuwen根进程设计；多个独立候选时DEGRADED，不任意选取。
- 已观察到的fork后代不会自动升为另一个根目标；首次扫描前已经孤立的子进程来源不能保证还原。
- 读取实际映射文件，通过 map_files 或核对设备/inode的目标root路径定位，避免挂到同名不同文件。
- 退出、同PID exec、重启会使旧目标失效，卸载后重新扫描适配；成功挂载增加代次。
- 失效和重挂期间可能缺证据；不回放已执行行为、不恢复此前在途工具绑定。
- marker是协作标识，不是安全认证或租户隔离机制。

## 4. Python 自动适配

当前探针模型限定 CPython 3.11，架构必须匹配：

1. 所需四个函数符号完整时，选择按符号解析/挂载。
2. 符号缺失时，仅在 Python 与 _asyncio 的双 Build ID 命中已验证配置时使用内置偏移。
3. 其他小版本、未知剥离构建等无法确认安全适配时降级，不猜地址。

不需要 ICAgent 提供 Python 路径、PID、偏移，也不会运行目标Python或将目标代码加载进
ICAgent。自动定位不等于任意Python版本兼容：真实采集验证为CPython 3.11.2 ARM64，
符号分支有ELF/规则测试，不能把它表述成所有3.11构建、3.11.4或3.12已完成真实验证。

## 5. 当前对外事件详细范围

公共字段见[接口说明](01-动态库接口说明.md)。以下JSON字段是当前输出使用的字段，
不是每条都齐全；可选值缺失必须按“未知”处理。容器和命令等信息可能来自尽力查询。

### 5.1 FILE_OPEN（类型1）

- 采集 open/openat 的调用入口，记录打开尝试。
- 主要JSON字段：event=FILE_OPEN、timestamp、pid、comm、filepath、flags、count，以及关联字段。
- 可知道工具试图打开哪个路径、使用什么打开标志，不能证明打开成功，也不代表实际读取。
- 没有实测打开耗时、返回FD、读取字节数或文件内容；duration_ns为未知。
- 库不只输出只读打开。若沿用旧转换器的只读过滤策略，需在ICAgent显式检查访问模式位；
  是否保留其他打开模式是产品规则，不能误认为库已替宿主过滤。
- 路径可能相对或截断，不能认为是规范化绝对路径；也不覆盖所有打开方式。

### 5.2 FILE_WRITE（类型2）

- 当前覆盖 write/pwrite64/writev 返回值>0的成功写入，并要求能够追踪对应文件描述符与工具上下文。
- 主要JSON字段：event=FILE_WRITE、timestamp、pid、comm、filepath、count、total_bytes及关联字段。
- count是聚合的成功操作次数，total_bytes是实际返回的写入字节之和，不是调用请求字节。
- 一条证据可能包含多次写入，不应展开成同样数量的伪造逐次调用span。
- 聚合timestamp使用最后一次记录时间；没有每次操作耗时或完整聚合起止时间。
- 有周期聚合排出，当前周期约5秒，停止等流程也会排出；不提供严格的5秒端到端时延保证。
- 返回0/失败的写入不在这类证据内；不包含内容，不证明fsync持久化。
- 无法覆盖所有mmap/io_uring等写入方式；未跟踪到FD等情况可能没有证据。

### 5.3 FILE_RENAME（类型3）

- 覆盖当前内核/架构可挂载的rename/renameat/renameat2路径，采集返回结果。
- 主要JSON字段：event=FILE_RENAME、timestamp、pid、comm、filepath、source_path、
  destination_path、source_dirfd、destination_dirfd、rename_flags、count、syscall_name、
  syscall_return、duration_ns；失败时增加syscall_errno。
- filepath是输出中的目标路径别名；转换优先使用明确的source_path/destination_path。
- syscall_return<0表示失败，正常内核errno范围内会输出对应正值syscall_errno；耗时来自入口到出口测量。
- timestamp保留重命名入口时间，出口补充结果和duration_ns；这一类型可按入口加耗时计算结束时间。
- 这是重命名证据，不代表工具整体成败；工具可能捕获错误重试。
- 路径有长度限制，过长等情况可能拒绝生成记录；不保证每次操作都能观察到。

### 5.4 PROCESS_EXEC（类型4，JSON event=EXEC）

- 捕获成功的程序映像执行切换，不是所有fork创建，也不是完整命令生命周期。
- 主要JSON字段包含timestamp、pid、comm、filename、full_command、ppid等，以及关联字段；
  具体命令/进程补充信息按实际可获得情况处理。
- 可以说明工具关联的进程执行了什么程序；不能说明命令最终成功、退出码或总耗时。
- 失败的exec不属于当前此类输出。EXIT等内部事件参与清理，但不作为公开证据类型输出。
- 命令和路径有长度限制，可能含敏感参数，不能当作无损、已脱敏的完整审计日志。

### 5.5 关联与时间字段

JSON可包含agentsight_task_id、agentsight_bound_task_id、agentsight_correlation_source、
agentsight_trace_id、agentsight_parent_span_id、agentsight_trace_flags等字段。
correlation source目前有task、task_parent、py_context、process等路径。
建立父子关系优先用公共结构中的ID字节，诊断时保留来源；不能仅用Task地址认定永久身份。

wall_time_ns是换算值，存在时钟偏差风险；duration_ns=0是未知，不是测得零耗时。
rename有实际耗时，但当前四类事件的timestamp含义并不完全一致，不能机械地给所有事件
使用“timestamp+duration”来猜结束时间；转换规则需双方确认并测试。

## 6. 执行模型覆盖与未支持项

| 模型 | 当前范围 |
|---|---|
| 普通sync/async LocalFunction | 当前正式callback真实测试覆盖 |
| 并行工具、gather场景 | 当前测试覆盖工具隔离 |
| 工具内create_task并等待 | 当前测试覆盖task_parent关联 |
| asyncio.to_thread | 当前测试覆盖PyContext关联 |
| 工具启动并等待短生命周期子进程 | 当前测试覆盖process关联 |
| 工具异常结束 | 当前测试覆盖清理及工具外行为隔离 |
| 任意run_in_executor/普通线程池 | 不保证自动传递上下文，不等于to_thread |
| 工具返回后继续运行的后台Task | 不支持可靠归属到已结束工具的通用模型 |
| 长期复用stdio MCP Server | PID不足以区分请求，当前不支持请求级通用关联 |
| 远程HTTP/MCP、非CPython runtime | 当前未支持，需独立的跨进程/跨服务方案 |

历史穿刺的TaskGroup、取消等场景记录不等于本版全部重新验收；实际复测范围以本包
报告和断言为准。任务地址/context/PID复用、map容量、父链和栈深限制仍是生产化关注项。

## 7. 可观测性、故障与数据边界

- 只提供有界内存队列，不提供持久化、ACK、补采、可靠重放。
- 队列满丢新证据并计数，读取速度和下游队列由宿主管理。
- 提供发现、挂载、状态、错误、用户队列及部分内核丢弃统计，不覆盖所有证据缺失原因。
- 增强发现/适配失败应只造成增强缺失，不能阻断原始工具或原始OTel；原生库崩溃仍会影响宿主。
- 没有业务资源/租户完整上下文，没有内置通用脱敏、租户鉴权、逐工具配额或路径过滤API。
- 当前没有read字节、文件内容、删除/mkdir对外事件、网络/DNS/HTTP/HTTPS证据、LLM重建和OTLP exporter。
- 没有证据可能是未绑定、未就绪、未采样、不支持、丢失或确实无行为，不能简化成“没有执行”。

## 8. 部署条件和验证证据

主场景为宿主机ICAgent、一个独立Jiuwen根进程。容器ICAgent需要宿主PID namespace及
正确procfs/目标映射可见性；只挂宿主/proc而不共享PID namespace目前不支持。
宿主/proc自检也不保证完整宿主可见性，权限与安全策略需要部署验证。
业务实际加载marker与探针目标文件必须对应，不能仅拿另一个同名副本挂载。

已记录验证环境：Linux ARM64，内核6.6.0-28.0.0.34.oe2403.aarch64，CPython3.11.2，
Go1.21.4。最高依赖glibc符号GLIBC_2.34不是所有发行版兼容认证。

| 验证 | 已记录结果 |
|---|---|
| Rust单元测试 | 12/12 |
| C/C++ ABI及Go消费 | 通过；布局32/88/192 |
| 正式callback、业务先启动 | 16个tool span、71条关联证据 |
| 正式callback、库先启动 | 16个tool span、71条关联证据 |
| 关闭增强 | 16个tool span、0条证据 |
| 未知stripped构建 | DEGRADED，业务正常、0条证据 |
| 自动发现/生命周期 | 9项通过，明细见TEST_REPORT |

当前真实测试用正式agent-core/JiuwenSwarm callback和测试消费端，不是Jaeger验收。
未完成：真实ICAgent插件、私有huaweicloud-instrument接线验证、这版增强span上报Jaeger、
x86_64、广泛Python/内核矩阵、生产压测及完整多租户隔离。本次文档整理不重跑上述采集测试。
