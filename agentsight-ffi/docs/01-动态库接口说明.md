# libagentsight 动态库接口说明

面向 ICAgent 接入开发者。本文描述当前已实现的 C ABI，不是未来接口方案。
配套文件：[agentsight.h](../include/agentsight.h)、[Go 示例](../examples/go/main.go)。
版本：采集库 ABI **2**，事件 schema **1**，业务 marker ABI **1**；三者独立。
本次仅补充文档与消费示例，不改变二进制。当前 ARM64 交付的 Config/Event/Stats
大小为 32/88/192 字节；代码必须使用配套头文件的 sizeof，禁止硬编码大小。

## 1. 通用调用契约

- `AgentsightHandle` 是不透明句柄；不能复制其内部内容、解引用或自行释放。
- 除版本值、fd、事件数量和 void 返回外，成功返回 0，失败返回负 errno。
  错误直接来自返回值，不应读取调用线程的 errno 来替代。
- 接受 handle 的常规接口：NULL 返回 `-EINVAL`；fork 继承的句柄返回 `-ECHILD`。
  `free(NULL)` 是特例，成功返回 0。
- 可捕获的 Rust unwind 返回 `-EFAULT`；这不是对段错误、abort、内存破坏、OOM 的隔离。
- 生命周期操作建议串行；一个 handle 使用一个事件消费者；free 不得与任何使用同一
  handle 的调用并发。禁止伪造指针、悬空指针、重复释放。参数检查不能保证识别这些错误。
- 库初始化后 fork 出的子进程必须 exec 后再使用库，不能复用继承状态。
- 不修改宿主信号处理，不自动提权、不提高 RLIMIT_MEMLOCK，不启动独立 collector。
- 当前没有 suspend、热更新配置、事件 ACK、持久化重放或上报接口。

## 2. 生命周期和通知顺序

```text
abi_version → init → set_config → start
                              ↓
              get_eventfd → poll/epoll 等待通知
                              ↓
                    poll_events → 复制事件 → free_event
                              ↓
                  周期 get_stats，失败时 get_last_error
                              ↓
              stop → poll_events 排空 → 解除 fd 监听 → free
```

`start` 成功只表示发现线程已启动。`state=RUNNING` 不代表 `target_state=READY`。
Jiuwen 未启动时等待是正常状态。目标不兼容、权限不足等可能在 start 返回后表现为
DEGRADED，应查询统计，不要只检查 start 返回码。

停止后需要排空用户态队列才能重新配置或启动。重启会重建关联状态，不恢复在途工具
绑定，不补采停机期间行为。已入队事件保留产生时的原始关联 ID。

## 3. 函数逐项说明

### 3.1 agentsight_abi_version

```c
uint32_t agentsight_abi_version(void);
```

- 输入：无。
- 输出：当前为 2，不是成功/失败码。
- 作用：在使用结构体和其他接口前，与头文件 `AGENTSIGHT_ABI_VERSION` 比较。
- 不一致时停止接入，不尝试按旧结构读取新库。

### 3.2 agentsight_init

```c
int32_t agentsight_init(AgentsightHandle **out);
```

| 参数 | 方向 | 要求 |
|---|---|---|
| out | 输出 | 指向一个可写的 handle 指针变量，例如 `&h`；不能为 NULL |

- 作用：创建未启动的句柄、队列管理和内部通知资源；不挂载探针。
- 成功：返回 0，`*out` 为有效句柄，状态 INITIALIZED。
- 失败：合法 out 会先被置 NULL；可能返回 `-EINVAL`、`-ECHILD`、eventfd 系统错误或 `-EFAULT`。
- init 失败没有有效 handle，不能调用 get_last_error(NULL) 取得初始化诊断；记录返回码。

### 3.3 agentsight_set_config

```c
int32_t agentsight_set_config(AgentsightHandle *h, const AgentsightConfig *config);
```

| 参数 | 方向 | 要求 |
|---|---|---|
| h | 输入 | 本进程创建且未释放的句柄 |
| config | 输入、仅调用期间借用 | 指向有效配置，字段见第 4 节 |

- 作用：检查并复制配置，包括 procfs_root 字符串。返回后可释放调用方配置字符串。
- 成功：0，状态 CONFIGURED。
- `-EINVAL`：NULL 配置、大小/ABI 不匹配、路径或数值超范围。
- `-EBUSY`：工作线程仍存在或旧事件队列未清空。失败不应用新配置。
- 即使后台线程已失败，也先 stop 回收线程，再排空队列、重新配置。

### 3.4 agentsight_start

```c
int32_t agentsight_start(AgentsightHandle *h);
```

- 输入 h：已成功配置的有效句柄；无输出参数。
- 作用：启动发现/采集后台线程；不等待业务进程出现。
- 成功：0。正在 RUNNING 时重复调用也是 0。
- `-EINVAL`：尚未 set_config。
- `-EBUSY`：另一个采集实例活跃、旧队列未排空，或旧线程尚未回收。
- 也可能返回创建线程的系统错误、启动握手失败等负错误码。
- 同一库实例允许多个未启动 handle，但只允许一个活跃采集实例。

### 3.5 agentsight_stop

```c
int32_t agentsight_stop(AgentsightHandle *h);
```

- 输入 h：有效句柄；无输出参数。
- 作用：发出停止请求，唤醒并等待后台线程结束，卸载探针、处理内核聚合数据。
- 成功：0，允许未启动时调用及重复调用；工作线程异常可能返回 `-EFAULT`。
- 这是等待线程结束的调用，不是立即返回的暂停请求；当前不提供停止超时参数。
- 用户态队列仍可读取；内核排出数据仍可能因队列满而丢弃，不能承诺无损。
- 不保证所有失败路径都将 state 改为 STOPPED，应结合状态与返回码诊断。

### 3.6 agentsight_free

```c
int32_t agentsight_free(AgentsightHandle *h);
```

- 输入 h：待释放句柄，NULL 允许；无输出参数。
- 作用：必要时先 stop，丢弃未取出的队列数据，关闭库拥有的 fd 并释放句柄。
- 成功：0；调用方应将自己的 h 置 NULL，禁止再次使用原值。
- 如果内部 stop 失败，返回该错误且不会继续释放；不要把失败当作释放成功。
- 已经 poll 取出的事件独立存活，可以在 handle 释放后 free_event。
- 必须在卸载 `.so` 前释放全部事件；free 不自动把调用方变量改成 NULL。

### 3.7 agentsight_get_eventfd

```c
int32_t agentsight_get_eventfd(AgentsightHandle *h);
```

- 输入 h：有效句柄，init 后即可调用；无输出参数。
- 成功：返回非负 fd（0 也合法），失败返回负错误码。
- fd 为库拥有的 nonblocking、close-on-exec 通知描述符；直到 free 前有效，stop 不关闭它。
- 仅用于 poll/epoll 观察可读性，禁止宿主 read/write/close。
- 它不是事件数据通道。状态变化、后台结束也可能触发通知，唤醒后可能没有数据。
- poll_events 负责清除通知；若队列仍非空，会重新通知。

### 3.8 agentsight_poll_events

```c
int32_t agentsight_poll_events(AgentsightHandle *h,
                             AgentsightEvent **out_events,
                             uint32_t capacity);
```

| 参数 | 方向 | 要求 |
|---|---|---|
| h | 输入 | 有效句柄；停止后仍可读取 |
| out_events | 输出 | 指向可写事件指针数组，至少 capacity 个指针槽；不是连续的事件结构数组 |
| capacity | 输入 | 本批最大条数，1～65536；不是字节数 |

- 非阻塞。返回 n>0 表示写入前 n 个指针槽；0 表示此刻队列为空；负数表示错误。
- 未使用的指针槽不清零，禁止遍历至 capacity 来释放旧指针。
- 数组 NULL、capacity 不合法返回 `-EINVAL`；其他通用错误见第 1 节。
- 每个返回指针的释放责任交给调用方，必须 free_event 恰好一次。
- 出队即从库内 queued_bytes 扣除；宿主持有未释放事件不再受队列预算约束。
- cgo 的输出指针数组使用 C.malloc。数组自身用 C.free，事件用 free_event，两者不能混用。
- 建议通知后分批取到 0；长期高负载下宿主应兼顾停止和状态检查，避免无限处理循环饥饿。

### 3.9 agentsight_free_event

```c
void agentsight_free_event(AgentsightEvent *event);
```

- 输入 event：poll_events 返回的事件指针，NULL 是无操作。
- 返回：无。释放事件及其 payload_json，不需要分别释放 JSON。
- 不得用 libc free/delete 替代；释放后不能读取结构或其借用字符串/切片。
- 解析失败、过滤、下游队列满时仍须释放；禁止与事件读取并发或重复释放。

### 3.10 agentsight_get_last_error

```c
int32_t agentsight_get_last_error(AgentsightHandle *h, char *buffer, size_t capacity);
```

| 参数 | 方向 | 要求 |
|---|---|---|
| h | 输入 | 有效句柄 |
| buffer | 输出 | 调用方分配的可写缓冲区 |
| capacity | 输入 | 缓冲区字节数，包含结尾 NUL 空间，必须 >0 |

- 成功 0：文本完整复制，NUL 结尾；没有文本时得到空串。
- `-ENOSPC`：内容截断，仍保证 NUL 结尾；可增大缓冲区重试，但期间文本可能变化。
- `-EINVAL`：NULL 缓冲区或容量为 0；另有通用 handle 错误。
- 文本属于 handle 的最近诊断，非线程局部，也不严格对应最近一次 API 错误；后台可以覆盖。
- 不返回所需长度；建议先分配 2048 字节。以原 API 返回码为准，不用旧文本判断新操作失败。

### 3.11 agentsight_get_stats

```c
int32_t agentsight_get_stats(AgentsightHandle *h,
                            AgentsightStats *stats, size_t stats_size);
```

| 参数 | 方向 | 要求 |
|---|---|---|
| h | 输入 | 有效句柄 |
| stats | 输出 | 指向可写统计结构 |
| stats_size | 输入 | 可用缓冲区字节数，至少 sizeof(AgentsightStats) |

- 成功 0：填入快照，库自行填写 struct_size/abi_version，调用方无须预填这两个字段。
- NULL stats 或空间过小返回 `-EINVAL`；另有通用 handle 错误。
- 失败时不要使用输出内容。统计随 handle 累计，stop/start 不清零；新 handle 从零开始。
- 状态为快照，不是对未来采集持续成功的保证。

## 4. AgentsightConfig 全字段

先清零整个结构，再填写两个必填字段。

| 字段 | C 类型 | 单位、默认值与约束 |
|---|---|---|
| struct_size | uint32_t | 必须等于 sizeof(AgentsightConfig)；这里不是“至少” |
| abi_version | uint32_t | 必须等于 AGENTSIGHT_ABI_VERSION，即 2 |
| queue_capacity | uint32_t | 条数；0→1024，非零 1～65536 |
| discovery_interval_ms | uint32_t | 毫秒；0→1000，非零 100～60000 |
| max_queue_bytes | uint64_t | 字节；0→16MiB，非零 1024～1073741824 |
| procfs_root | const char * | NULL/空串→/proc；否则为 NUL 结尾绝对路径，长度小于4096字节 |

队列条数或字节任一达到限制即丢新事件。字节预算覆盖排队 payload 和事件元数据，
不覆盖 BPF map/ring、解析临时内存、容器分配开销、已经取出的事件或宿主队列，不能当作 RSS 限额。
procfs 路径不改变 PID namespace；当前要求宿主 PID 视角，不能仅靠 bind-mount 解决。
当前不接收目标 PID、marker/Python 路径、偏移、网络目标或过滤规则。

## 5. AgentsightEvent 全字段

| 字段 | C 类型 | 含义 |
|---|---|---|
| struct_size | uint32_t | 库返回的事件结构大小 |
| schema_version | uint32_t | 当前 1，不是库 ABI 版本 |
| event_type | uint32_t | 1=FILE_OPEN，2=FILE_WRITE，3=FILE_RENAME，4=PROCESS_EXEC |
| trace_flags | uint32_t | 从原始工具 context 获取的标志；当前只返回 sampled 位已置位的事件 |
| pid | uint32_t | 行为进程 ID；子进程行为可能不是 Jiuwen 根 PID；缺失时可为0 |
| tid | uint32_t | 行为线程 ID；不是所有来源都提供，缺失时可为0 |
| timestamp_ns | uint64_t | 内核 CLOCK_MONOTONIC 纳秒，不是 Unix 时间 |
| wall_time_ns | uint64_t | 双时钟锚点换算的 Unix 纳秒估计值；不承诺无时钟偏差 |
| duration_ns | uint64_t | 纳秒；0=未知，不是实测零耗时；rename 可含实测耗时 |
| trace_id | uint8_t[16] | 原始 trace ID 的网络序字节，不是 C 字符串 |
| parent_span_id | uint8_t[8] | 原始 tool span ID 的网络序字节；宿主另生成新子 span ID |
| payload_json | const char * | 只读、NUL 结尾的 JSON；事件释放前有效 |
| payload_json_len | uint32_t | JSON 字节长度，不含尾部 NUL；复制时优先使用该长度 |
| reserved | uint32_t | 当前为0，保留，不赋予业务含义 |

不要把 ID 数组按宿主端序整数重新解释；需要文本时按字节编码为32/16个十六进制字符。
payload 各类型字段与缺失规则见[功能说明](03-当前版本功能与边界.md)。JSON 字段不是所有事件
都齐全，解析器应容忍额外字段，并区分不存在和数值0。没有完整 service.name、租户资源信息。

## 6. AgentsightStats 全字段

以下计数均为 uint64_t，除非表中另标类型。累计计数建议以增量监控，不要每轮求和。

| 字段 | 含义与口径 |
|---|---|
| struct_size (uint32_t) | 库写入的结构大小 |
| abi_version (uint32_t) | 当前2 |
| state (uint32_t) | INITIALIZED=0、CONFIGURED=1、RUNNING=2、STOPPED=3、FAILED=4 |
| supported_counters (uint32_t) | 位图：USER_QUEUE=1、AGG_OVERFLOW=2、KERNEL_RING=4；按位测试 |
| received_records | 底层普通输出记录数，含内部时钟/统计记录，不等于工具操作数 |
| filtered_records | 不支持的类型、无效关联或未采样等被过滤的记录数 |
| invalid_records | JSON、时间字段/锚点等无效记录数 |
| enqueued_events | 成功进入用户队列的事件数 |
| delivered_events | poll 已交给宿主的事件数，不是上报成功数 |
| queue_dropped_events | 用户队列条数/字节限制导致的新事件丢弃 |
| output_dropped_records | 底层输出序列化等路径主动报告的丢弃记录 |
| backend_errors | 已统计的采集后台错误；不覆盖所有目标降级情况 |
| backend_diagnostics | 底层诊断消息数，不应直接当作失败操作数 |
| aggregate_overflow | 既有聚合 map 溢出计数，尽力统计，不是所有内核丢失 |
| queued_events | 当前仍在库内排队的事件数（瞬时值） |
| queued_bytes | 当前排队预算占用（瞬时值），不是进程 RSS |
| target_state (uint32_t) | IDLE=0、WAITING=1、ATTACHING=2、READY=3、DEGRADED=4 |
| target_pid (int32_t) | 当前状态关联的目标PID，无目标可为0；降级时可能保留上次身份 |
| target_start_ticks | /proc/PID/stat 的 starttime，单位 clock ticks，不是纳秒 |
| target_generation | 每次成功挂载增加的代次；不是每条事件所携带的字段 |
| discovery_scans | 扫描次数 |
| discovery_errors | 扫描报错次数 |
| attach_attempts | 实际尝试挂载次数 |
| attach_failures | 挂载失败或挂载期间目标变化次数 |
| target_detaches | 已激活目标的卸载次数 |
| target_error (int32_t) | 当前发现/适配/挂载错误，负 errno 或0；配合最近诊断文本 |
| adaptation_method (uint32_t) | 未 READY 为0；SYMBOLS=1，BUILD_ID=2 |
| kernel_ring_dropped | 增强 open/rename/exec/exit 探针 ring 申请失败计数 |

WAITING 表示等待业务，不一定异常；DEGRADED 表示当前不能正常增强但可继续发现重试。
不能只看 backend_errors=0 来判断健康。上述计数尚未覆盖所有关联 map 满、上下文丢失和
不支持路径；不能据计数全0证明没有漏采。当前目标快照不能用来覆盖排队旧事件的身份。

## 7. 所有权速查

| 对象 | 谁创建 | 谁释放 | 时机 |
|---|---|---|---|
| 配置结构/字符串 | 宿主 | 宿主 | set_config 返回后可释放 |
| handle | 库 | 宿主调用 agentsight_free | 所有同 handle 操作停止后 |
| eventfd | 库 | 库 | 随 handle 释放，宿主只解除监听 |
| poll 指针数组 | 宿主 | 宿主 | 不再用数组时；cgo 使用 C.malloc/C.free |
| 返回的事件及 JSON | 库 | 宿主调用 agentsight_free_event | 完成复制后恰好一次 |
| 错误/统计输出缓冲区 | 宿主 | 宿主 | 同步调用及使用完毕后 |

## 8. 常见错误处置

| 表现 | 应检查 |
|---|---|
| ABI 不一致 / stats buffer too small | 配套头文件和库，强制重新编译 cgo；不要忽略错误继续读 |
| set_config/start 返回 -EBUSY | 是否 stop 旧线程、排空队列，是否存在另一活跃实例 |
| start=0 但没有事件 | target_state、marker接线、采样、是否有工具内行为；0条不是错误本身 |
| DEGRADED | get_stats.target_error 和 get_last_error；权限、procfs、Python兼容、多目标等 |
| get_last_error=-ENOSPC | 缓冲区太小，文本已截断且NUL结尾，扩大缓冲区 |
| -ECHILD | fork 后使用了继承状态，子进程需要 exec |
| 队列丢弃增长 | 加快消费、限制下游阻塞、合理配置预算；不是保证可恢复的错误 |

其他系统错误可能随环境变化；以上不是穷举。故障不能通过伪造上下文或猜测偏移绕过。
