# ICAgent 适配需求与验收清单

本文是给ICAgent团队的需求输入，不假设其现有框架已经有“插件创建span”入口，也不指定
包路径、类名、线程模型、SDK或内部实现。已有能力可以复用，缺少能力由ICAgent补齐。
库接口、使用示例、现有能力分别见本目录01/02/03文档。

## 1. 目标和范围

ICAgent加载libagentsight，消费已关联的系统证据，生成原始工具span的证据子span，
通过统一trace链路送达后端。保持原始Jiuwen trace层级和原始上报不变。

```text
原始 tool span
├── agentsight.file.open
├── agentsight.file.write
├── agentsight.file.rename
└── agentsight.process.exec
```

不是重新创建原始tool/LLM span，不修改或重新结束已导出的tool span，不另起AgentSight
独立exporter。ICAgent只需接收确定的关联ID，不负责事后猜父span。

## 2. 责任边界

| 事项 | 责任方 |
|---|---|
| 创建正式tool span、加载marker、bind/unbind | Jiuwen侵入式插桩维护方 |
| 自动发现、Python适配、挂载/卸载、系统行为采集、工具身份关联 | libagentsight维护方 |
| 公开事件格式、状态错误、当前支持的丢弃统计 | libagentsight维护方 |
| 加载配置启停、读取释放、转换span、资源归属、安全处理、上报和宿主指标 | ICAgent团队 |
| 具体字段映射、资源/租户归属规则、缺口与错误展示、端到端验收 | 双方联合确认 |

不要求ICAgent提供进程清单、进程启停通知、目标PID、Python偏移或路径。
实际私有插桩包与ICAgent未提供给库维护方，不能把本地callback验证当作私有系统已接入。

## 3. 必须实现的能力

### R01：产物管理与可选加载

- 管理匹配的架构、库版本、头文件和系统依赖，启动检查ABI。
- 提供默认关闭的增强开关；不可因默认部署了库就自动采集所有工作负载。
- 库缺失、版本不兼容、依赖不满足时，增强不可用但ICAgent其他能力应正常运行。
- 具体可选加载机制由ICAgent选择；直接cgo链接示例不能保证缺库时宿主仍能启动。
- 不得用amd64源码build tag证明ARM64二进制可跨架构。
- 原生段错误/OOM的进程级风险需纳入运行风险评估；接口错误处理不是进程隔离。

验收：移除增强库或提供不匹配版本时，主框架仍能正常启动，并明确记录增强不可用。

### R02：配置与单实例管理

- 下发procfs_root、discovery_interval_ms、queue_capacity、max_queue_bytes。
- 按公开范围校验配置，禁止误把队列字节预算解释为整个ICAgent内存限额。
- 节点内管理一个活跃采集实例，避免多条插件配置重复启动。
- 不要求等待Jiuwen就绪才启动ICAgent或调用start。
- 配置更新采用stop、排空、set_config、start；当前库无热更新/suspend协议。
- 停止、关闭、异常退出及升级必须有明确资源清理和未处理数据丢弃策略。

验收：两种启动顺序正常；配置切换不泄漏handle/fd；剩余数据处理可计数，不能静默遗留。

### R03：事件消费与所有权

- 获取通知fd，等待后批量读取；处理超时、空队列和状态变化通知。
- 一个handle一个消费者；free前结束所有使用该handle的任务并解除fd监听。
- 数据复制到宿主管理内存后释放原生事件；异常、过滤和丢弃路径同样必须释放。
- 原生事件只用free_event释放，通知fd不自行read/write/close。
- 下游网络处理不得长期阻塞读取；宿主下游队列也必须有界。
- 正常停止先stop，再排空或按约定丢弃并计数，最后free。

验收：正常、解析异常、队列满、停止等路径无事件重复释放或持续内存增长；所有取出的
事件都有明确处理结果。长期压测与内存阈值由双方另定，不以一次冒烟替代。

### R04：生成增强span

- 新span使用事件trace_id和parent_span_id；另生成非零的新span ID。
- 不使用PID、时间、路径、名称或当前目标快照猜测父span；无合法关联时丢弃并计数。
- 按四类事件生成结构化span属性，而不是仅上传一条无结构JSON日志。
- 保存实际已知的路径/命令、操作结果、写入次数和字节数、关联来源等信息。
- 明确瞬时证据、聚合证据与有实测耗时的操作差别；不得编造耗时、成功状态或文件内容。
- 原工具结束后仍可发送子span，不重新打开/结束/上报原工具span。
- 保持原始采样语义；当前库已过滤未采样/无效关联，不另造上下文。
- 上报重试复用同一个已生成span ID，避免每次重试变成新证据。

验收：后端查询到正确trace和父ID，增强span ID不与工具ID相同；并行工具不串关联。

### R05：事件转换规则

| 事件 | 最低保留信息 | 禁止误述 |
|---|---|---|
| FILE_OPEN | 路径、flags、打开尝试语义 | 不能标记为已读取文件内容或必然打开成功 |
| FILE_WRITE | 路径、count、total_bytes、聚合标识 | 不能伪造逐次耗时、失败写入或持久化成功 |
| FILE_RENAME | 源/目标、syscall_return、可用errno、实测耗时 | 单个操作失败不自动修改工具总体状态 |
| PROCESS_EXEC | 可用程序/命令及进程信息 | 不能当作命令已结束或成功退出 |

必须形成可测试的字段映射表，包括属性键、字段类型、可选字段缺失、长度限制、未知
schema/type处理策略。schema变化不可静默按旧语义解释；额外可选JSON字段可容忍。
open是否只保留只读模式、span kind、未知耗时的时间表达需共同冻结；本表不擅自替代产品决定。

### R06：业务身份、资源与租户路由

- 确定增强span的service.name及资源属性来源，不默认套用ICAgent自身身份。
- 明确节点、容器、业务、租户信息来源和缺失时策略，不猜标签。
- 不能用get_stats的当前target_pid/generation覆盖旧队列事件身份或子进程身份。
- 当前事件没有完整原始OTel Resource、租户信息和事件级target_generation；不能要求
  接入方从不存在的字段读取这些信息。需要新字段时由双方另行评审库协议。
- 无法确认租户时，按约定进入安全的拒绝/隔离处理，不能发到推测租户。

验收：正确进入约定业务与租户；重启排队旧事件不被错误标为新实例；身份缺失处理可追踪。

### R07：统一trace上报

- 无论当前框架是否已有入口，都需提供把新生成增强span提交到trace后端的能力。
- 复用或接入统一鉴权、路由、批量与上报管理，不启用AgentSight原collector的独立上报。
- 明确内存队列、重试、退避、超时、最终丢弃规则，限制后端异常时资源占用。
- 区分“库已交付”“宿主转换完成”“进入上报队列”“后端确认”，不能只展示delivered_events。
- 库无持久化/ACK；如产品要求重启不丢数据，需另行定义宿主持久化能力，当前不承诺。

验收：Jaeger中可查询增强span；后端不可用时不阻塞原始业务，恢复与最终丢弃符合策略。

### R08：安全与数据控制

- 文件路径、命令行可能含凭据或个人信息；应在日志、队列持久化及上报之前按策略过滤/脱敏。
- 不直接将demo打印原始JSON的行为用于生产日志。
- 设定事件/属性大小与数量限制；过滤、脱敏失败和限流有对应计数。
- 明确与原始trace相匹配的租户隔离、保留和访问控制要求。
- marker名称识别不等于可信认证；部署权限范围由安全评估确定。

验收：带敏感参数的测试证据不会原样进入不允许的日志/后端；限流有明确指标。

### R09：状态与诊断

- 对外区分关闭、加载失败、等待目标、挂载中、就绪、降级、停止/故障。
- RUNNING仅代表线程运行，只有READY才表示探针当前就绪。
- 暴露target_error及诊断原因，正常等待避免刷错误日志；重试失败日志应控制频率。
- 监控发现/挂载、库内积压/丢弃、宿主解析/转换/队列/上报错误，按不同阶段分开。
- 当前丢弃统计不是全面漏采计数，不允许展示“0丢弃=完整采集”的保证。
- 启动、重挂和停机的证据缺口必须在运维语义中说明，不能把无证据解释为无行为。

验收：缺权限、未知Python、多候选、后端故障可被区分定位；无需阅读源码即可知道在哪一层失败。

## 4. 接口覆盖检查

| 能力 | 公开接口 |
|---|---|
| 兼容检查 | agentsight_abi_version |
| 创建配置 | agentsight_init、agentsight_set_config |
| 启停释放 | agentsight_start、agentsight_stop、agentsight_free |
| 通知读取 | agentsight_get_eventfd、agentsight_poll_events |
| 内存释放 | agentsight_free_event |
| 诊断统计 | agentsight_get_last_error、agentsight_get_stats |

要求完整处理这11项职责，不要求向最终用户暴露11个配置按钮或外部API。

## 5. 联合验收用例

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 库/依赖缺失或ABI不匹配 | 增强不可用有原因，ICAgent其他能力正常 |
| A02 | ICAgent先启动，Jiuwen后启动/延迟加载marker | 从等待到READY，后续工具证据可查询 |
| A03 | Jiuwen先启动 | 发现并挂载，不要求重启整个ICAgent；挂载前行为不补采 |
| A04 | 四类证据上报 | 字段语义正确、同trace、父tool正确、新span ID |
| A05 | 并行、子Task、to_thread、短子进程 | 支持范围内不串关联；不将未知模型当作支持 |
| A06 | 工具异常/工具外行为 | 绑定清理，工具外证据不误挂 |
| A07 | Jiuwen退出/重启、同PID exec | 卸载重挂，排队旧证据身份不被覆盖 |
| A08 | 关闭增强 | 原始trace正常，无新增强证据 |
| A09 | 权限不足/未知Python/多个独立候选 | 可解释降级，不猜目标/偏移，不影响原始工具 |
| A10 | 高负载、队列满、慢消费 | 内存有界，丢弃可观测，释放正确 |
| A11 | 后端不可用及恢复 | 有界重试、ID稳定、不阻塞采集；最终丢弃可统计 |
| A12 | stop/配置更新/再次start/退出 | 剩余事件处理清楚，无资源遗留，不承诺恢复旧绑定 |
| A13 | 跨容器部署及敏感字段 | PID/文件视角正确、租户归属正确、脱敏有效 |

后端验收必须保存trace查询结果与ID断言，不能仅用打印JSON或库delivered计数替代。
本表是待完成的ICAgent联合验收，不表示这些用例已在真实ICAgent上通过。

## 6. 联调前需要冻结的规则

1. 增强span名称、属性键、span kind、未知耗时及错误的表达。
2. open保留范围、聚合write粒度、敏感字段脱敏策略。
3. service.name/租户/容器身份来源及缺失处理。
4. 宿主队列限额、重试上限、停机排空时限和最终丢弃规则。
5. 部署支持矩阵、性能/稳定性验收阈值和证据保留方式。

这些是需要双方确认的接入规则，不是要求提供ICAgent内部代码，也不预设其实现方式。
